## 1. 架构总览

### 1.1 系统上下文

```

└──────────────┬──────────────────┘
               │ HTTP  /api/v1/agent/*

┌─────────────────────────────────┐
│     Flask Backend (WSGI)        │
│     http://localhost:5000       │
│  ┌────────────────────────────┐ │
│  │  agent_bp — 6 个 API 端点  │ │
│  │    ↓          ↓         ↓  │ │
│  │ CoPawAgent  Storage  _ok() │ │
│  └────┬──────────┬────────────┘ │
│       ▼          ▼              │
│  ┌────────┐ ┌──────────┐       │

### 1.2 架构风格

> 选择架构风格时思考：教学场景需要什么样的复杂度？分层带来什么好处？

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | React SPA + Flask REST API | 教学清晰度：前端独立开发服务器 |
| **单体部署** | 前后端各一个进程 | 不引入微服务复杂度 |
| **分层架构** | Route → Agent → Storage | 替换存储引擎时上层零改动 |
| **三级降级编排** | CoPaw → 百炼 → Demo 静默降级 | 外部 LLM 不可用时自动兜底，保证系统始终可用（对齐 04 R-04、05 AC-002-03） |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Route** | `agent_bp.py` | 参数校验、HTTP 状态码、traceId | 直接读写文件、调用 LLM |
| **Agent** | `agent.py` | 降级编排、结果组装 | 感知 HTTP 请求/响应 |
| **Provider** | `copaw_bridge.py` / `bailian_qa.py` | HTTP 调用外部 API | 操作本地存储 |
| **Storage** | `storage.py` | 文件 CRUD、数据校验 | 调用外部 API |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | React（Hooks）≥ 18 | 教学通用性最高 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，零配置启动 |
| 状态管理 | `useState` + `useEffect` | 8 个 state 变量足够 |
| HTTP 客户端 | `fetch` API | 浏览器原生，不引入 axios |
| 样式方案 | CSS Modules / 原生 CSS | 零依赖、教学透明度高，不引入 Tailwind 或 CSS-in-JS 额外概念 |

## 4. 三级降级编排

> 对齐 `07` 1.2 降级策略。画出降级链路，标明每级的 `answer_source` 和 `llm_used`。

```
ask(query, session_id)
  ├─[1] CoPaw  → {source:"copaw",  llm:true}

| 提供商 | 文件 | 配置检测 | 超时 | 错误处理 |
|--------|------|----------|------|----------|

## 5. 数据存储架构

### 5.1 存储演进路线

| 阶段 | 存储 | 变更范围 | 说明 |
|------|------|----------|------|
| **P0（当前）** | JSON 文件 | — | 适合教学 |
| P1 | SQLite | 仅替换 Storage 层实现，Route/Agent 零改动 | 单文件数据库，支持 SQL 查询与事务，适合中等并发的单机部署 |
| P2 | PostgreSQL | Storage 层 + 部署架构（新增数据库服务） | 生产级关系数据库，支持高并发、备份恢复与水平扩展 |

## 7. ADR（架构决策记录）

> 每条 ADR 记录一个"为什么选 A 而不选 B"的决策。至少写 2 条。

**示例 — ADR-001**：为什么选 Flask 而非 FastAPI？Flask 学习曲线低，无需 async/await，学员 Python 基础即可上手。

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Flask 而非 FastAPI | 学习曲线低，教学更适合 |
| ADR-002 | JSON 文件存储而非 SQLite/PostgreSQL | P0 阶段数据量小（≤ 百条），JSON 文件可直接查看和调试，降低学员数据库安装成本；通过 Storage 层隔离，后续迁移至 SQLite/PG 时上层零改动 |
| ADR-003 | 前端单页少组件而非多组件拆分 | 教学版仅 8 个 state 变量、4 个页面交互（会话列表/新建/删除/问答），拆组件反而增加 props 传递和文件跳转负担；待 P1 功能增多后再按职责拆分 |

## 8. 安全架构

> 对齐 `07` 4 安全需求。当前教学版与生产需求的差距。

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| 认证 | 无（开放访问） | JWT |
| CORS | 全开放 | 白名单 |
| 密钥 | 环境变量 `.env` | Vault / Secrets Manager |
| 输入校验 | Route 层校验 query 长度 1–500、session_id 非空（对齐 09 §8） | 增加 XSS 过滤与 SQL 注入防护 |
| 速率限制 | 无 | 按 IP / 用户限流，防止 LLM 接口滥用 |
| 日志审计 | traceId 链路追踪（对齐 09 §2） | 集中式日志收集 + 操作审计 |
