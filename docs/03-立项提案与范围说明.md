## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 用户访谈 |
| 关键信息提取效率低：希望快速提取关键信息，如评级，目标价，核心观点 | 会议 |
| 对比困难：多家券商的研报关键信息靠手工提取，归并 | 会议 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

【请在此处写 3~5 句提案概要】
在投研助手内交付：1. 研报上传，管理，关键信息提取；2. 针对同一公司不同来源的研报对比；3. 支持问答方式查询研报内容，并且有会话管理，可以查看历史对话；4. 对接大模型。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除 | 多租户/行级数据权限 |
| 研报上传，关键信息提取 | 研报解析（PDF/HTML 自动提取）— 延至 M2 迭代（来源 `02` S-01 需求1） |
| 研报对比，同一公司不同来源的多指标对比 | 舆情监控 / 关键词告警 — 延至 M3 迭代（来源 `02` S-01 需求3） |
| 问答形式查询研报内容 | 多券商研报对比表自动生成 — 延至 M2 迭代（来源 `02` S-01 需求4、S-02 问题2） |
| 能力探测 + 健康检查 | 跨系统股票数据聚合 — 延至 M3 迭代（来源 `02` S-02 问题3） |

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| 【请填写第 2 条】 研报格式| 【影响】 不支持的格式| 【应对措施】提前约定好格式 |
| 【请填写第 2 条】 研报内容过大 【影响】 提取时间过长|| 【应对措施】对研报大小提前约定好格式,缓存之前分析好的研报 |
