## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |
| 研报阅读耗时2-3h | AI辅助提取关键信息，阅读效率提升5倍 |
| 研报对比需手工整理 | 自动汇总问答记录，减少重复劳动 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 【从 03 §1 提取痛点】 | 【翻译成正面目标】 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 降级场景提问 | 用户提问 → LLM不可用→系统返回Demo兜底回答→用户知晓降级状态|
| SC-03 | 管理历史会话 | 用户打开首页→查看会话列表→点击某个会话→浏览历史会话→删除旧会话 |
| SC-04 | 运维健康检查 | 运维访问/health→查看各组件状态→发现degraded→排查数据目录 |

| 编号 | 规则 | 来源 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 历史记录查看 | **P0**  | 【场景】 |
| 健康检查 | **P1**  | 【场景】 |
| 能力探测 | **P1**  | 【场景】 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 数据完整性 | 删除会话后，关联问答记录0条残留 |
| 健康检查 | /health在正常/降级两种状态下都返回正确status |
