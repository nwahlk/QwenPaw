01项目概述

CoPaw 是一款自托管的个人 AI 助手框架，支持多代理管理、14 个聊天渠道、16+ 技能插件和多家 LLM 提供商。本方案旨在为管理控制台新增系统数据看板模块，提供全局视角的系统运行状态监控。

1.1 背景与目标

随着 CoPaw 管理的代理数量和渠道规模增长，运维人员面临以下挑战：

  • 信息分散：系统健康状态散落在 Token 用量、会话列表、心跳监控等独立页面
  • 缺乏实时性：无法实时感知代理运行状态、渠道连接异常
  • 被动响应：问题发生后才逐页排查，缺乏预警机制
  • 决策缺据：缺少聚合统计支撑容量规划和服务优化

06接口设计

新增 4 个 REST 端点 + 1 个 SSE 端点，均挂在 /api/dashboard/ 下，支持 /api/agents/{agentId}/dashboard/ 代理级路由。

MethodEndpoint描述响应
GET /api/dashboard/overview 系统概览数据 { active_agents, online_channels, active_chats, uptime_seconds, total_messages_today }
GET /api/dashboard/messages?days=7 消息趋势统计 { dates: [...], total: [...], by_channel: { channel_name: [...] } }
GET /api/dashboard/channels 渠道健康状态 [{ name, status, messages_today, last_active_at }]
GET /api/dashboard/agents 代理活动统计 [{ agent_id, name, messages, avg_response_ms, top_tools: [...] }]

07实施计划

按 3 个迭代交付，每个迭代 1 周，总计 3 周。P0 功能在第一迭代交付。

迭代一：核心看板 Week 1
P0 系统概览卡片 + 渠道健康状态 + SSE 推送基础设施
交付物：后端 DashboardRouter + DashboardService；前端 DashboardPage + OverviewCards + ChannelHealth
迭代二：数据分析 Week 2
P1 消息趋势图 + Token 用量看板 + 代理活动排行
交付物：MessageTrend + TokenUsagePanel + AgentActivity；消息统计聚合服务
迭代三：完善体验 Week 3
P2 定时任务状态 + 快捷操作入口 + i18n + 暗色主题 + 降级策略
交付物：CronOverview + 跳转链接 + 国际化文件 + E2E 测试

里程碑与验收标准

里程碑时间验收标准
M1: 核心看板可用Week 1 结束概览卡片 + 渠道健康数据正确展示；SSE 推送延迟 <3s

08风险评估

风险等级影响缓解措施
消息统计数据量大导致聚合慢 中 看板加载 >2s 预聚合 + 内存缓存 (TTL 5min)；大数据量时采样展示
渠道连接状态检测不准确 中 误报在线/离线 采用心跳超时判定（>60s 无心跳 = 异常），而非直接查询连接池
SSE 长连接断开导致数据不更新 中 看板数据过期 自动重连 + EventID 断点续传；30s 轮询兜底
部分渠道未暴露连接状态 API 高 渠道健康数据不完整 第一阶段标记为"不支持"，后续推动各渠道实现健康检查接口
Token 成本估算不准确 低 成本数据仅供参考 明确标注"预估值"；支持用户自定义单价配置
