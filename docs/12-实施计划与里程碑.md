## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 部分 | TC-M01-020～025 |
| **S2** 问答核心 | `POST /ask` 三级降级编排 + 前端提问区与打字机效果 + 记录落库 | REQ-002 | TC-M01-001、TC-M01-044 |
| **S3** 历史与状态 | 历史记录加载与渲染 + 能力探测芯片 + 健康检查 | REQ-003、REQ-004、REQ-005 | TC-M01-045、TC-M01-030、TC-M01-031 |
| **S4** 发布准备 | 全链路 E2E 验收 + 性能 SLO 达标 + 安全扫描 + Bug Fix + 演示走查 | 全部 REQ | TC 全量回归 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | Agent 编排 | `agent.py` 三级降级链路（CoPaw→百炼→Demo）、`copaw_bridge.py`、`bailian_qa.py` Provider 实现 | 对齐 `08` §4 降级编排，answer_source 正确返回 | S2 主推，S4 优化 |
| W4 | 前端视图 | React SPA：Sidebar 会话管理 + Main 三态渲染 + 输入区 + 能力芯片 | 对齐 `06` 全部 UI 规格，8 个 State 变量可审计 | S1～S3 逻渐进 |
| W5 | 状态机与能力探测 | `GET /capabilities` + `GET /health` 端点实现，前端能力芯片与健康状态渲染 | 对齐 `09` §1 端点 1/4，`05` US-004/005 AC | S3 |
| W6 | 测试门禁 | pytest fixture 搭建、P0 单元测试、E2E 主路径回归、SLO 性能断言 | 对齐 `13` TC 全量用例，覆盖率 ≥ 90% | S1 fixture，S2～S4 递增 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兜底 |
| JSON 文件并发写冲突 | 数据丢失或损坏 | 教学版单用户不并发；生产版迁移 SQLite/PG（对齐 `08` §5.1 P1） |
| 前端状态管理复杂度超预期 | 开发进度延迟 | 8 个 State 严格约束，不引入额外状态管理库（对齐 `08` §3） |
| S1 会话存储延期阻塞 S2 问答 | 关键路径阻塞，全链路延迟 | S1 优先保证 `create_session` + `get_sessions` 最小可用，删除功能可延至 S2 |
